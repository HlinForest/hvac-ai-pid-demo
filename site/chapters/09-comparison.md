# 09 换个工况：收益在哪里，成本又在哪里

到这里，我们已经有四种固定参数方法、两种在线调参方法，以及可连接真实模型的 LLM 实验。现在把对象、指标和图表统一起来，观察哪些改进保留、哪些随工况变化消失。

## 先完整运行，再比较

```bash
python -m hvac_pid all
```

默认包括 FNN 教师生成、两种 RL 各 500 回合训练、标称整定与比较。不发起 LLM 调用。若已完成单独的真实 LLM 实验，可以再次运行：

```bash
python -m hvac_pid compare
```

只有状态为 `complete`、种子、对象与预算匹配的 LLM 记录才进入固定参数比较；未完成记录仍可在第八章读取，不冒充完整实验。当前附带结果包括 DeepSeek Flash 的十五轮真实调用，标称与参数冻结实验实际比较了七种方法。

## 第一种比较：参数冻结，只改变对象

先在标称对象上得到所有初始参数。随后保持 Z-N、SIMC、BO、FNN 的固定参数不变；Q-Learning 和 DQN 保持网络或 Q 表不变，初始增益锚点也不变，但运行时继续按学到的策略选择增益。

这回答的是：**对象发生变化以后，原来整定和训练的结果还管不管用？**

### 标称对象

![标称对象上的七方法响应](/results/09-compare/nominal/response.svg)

<!--@include: ../generated/compare-nominal.md-->

这一批结果中，BO、FNN、LLM 和 Z-N 的 IAE 接近，两个 RL 方法没有达到它们的水平。LLM 比同预算 BO 降低约 0.52% 的 IAE，FNN 也略好于当前 BO。差距很小，不宜用一个种子判断普遍优劣。

Q-Learning 与 DQN 相比 SIMC 改善了 IAE，同时增加了指令变化。IAE 只优化温度误差，不会自动替你控制执行器动作频率。这里把两个指标并列呈现，不事后修改评分权重让某方法更好看。

### 延迟从 2 分钟增加到 5 分钟

## 第二种比较：遇到一台新对象

这次使用从未参与训练和验证的十二个对象。每个对象重新做阶跃辨识，Z-N 与 SIMC 重新计算，BO 重新搜索；FNN 从新的辨识结果预测参数，两个 RL 方法使用新的 SIMC 锚点，但模型权重都保持冻结。

这回答的是：**拿到新对象后，各方法怎样利用当前试验与过去的学习？** 它与上一节的“原参数应对变化”是两个实验，不混在一个平均分里。

<!--@include: ../generated/holdout.md-->

这里的 BO 搜索属于新对象的正常整定，不用于选择训练超参数。训练配置已经固定。LLM 的十二对象调用未执行，不会在普通 `compare` 命令里隐式增加收费请求。

## 成本需要分开看

<!--@include: ../generated/costs.md-->

BO 在当前对象上直接消耗二十次闭环仿真。FNN 的教师数据来自六十个训练或验证对象，每个二十次仿真，共 1200 次，之后还要做正则系数的验证比较。预测虽然快，前面的标签成本不能省略。

Q-Learning 和 DQN 都运行 500 回合、30,000 次两分钟交互，对应 600,000 个物理步。表中训练耗时包含训练对象的初始辨识，不包含后续十二对象验证。完整成本字段保存在各章的 `training.json`。

在线推理的实际调用次数与耗时单独保存在 `09-compare/frozen.csv`。固定方法不会在每个决策区间运行 AI，因此它们的在线 AI 调用次数为零。FNN 的一次推荐发生在闭环开始之前。

## 动手：重复五个种子

```bash
python -m hvac_pid repeat --seeds 0 1 2 3 4 --output outputs/repeated
```

查看 `summary.csv` 的均值、样本标准差和范围。这个命令会重新训练，而不是把同一个模型重复评估五次。对象分区保持固定，变化的是搜索和训练的随机性。

再挑一个实际问题继续实验：给 BO 更多试验机会，给 DQN 更多训练回合，或者给 LLM 同样的反馈预算。先固定要改变的量，再运行，保留原结果用于对照。
