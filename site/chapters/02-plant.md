# 02 看懂对象：先量出增益、惯性和延迟

控制器的输出只有在对象响应之后才会体现在温度上。若不知道对象有多慢、输入晚多久到达，直接比较一组 Kp、Ki 很容易把延迟造成的现象误认为算法效果。本章先不整定 PI，用一个固定的 0.5 制冷指令测阶跃响应，再用同一个模拟器反求 $K,\tau,L$。

## 运行阶跃实验

```bash
python -m hvac_pid plant
```

默认命令在 `outputs/tutorial/02-plant/` 生成：

| 文件 | 内容 |
|---|---|
| `step.csv` | 240 分钟阶跃实验，含 2401 个温度样本 |
| `step.svg` | 默认对象和参数扰动响应曲线 |
| `identification.json` | 拟合得到的 `gain/tau/delay` |

实验从环境平衡温度 30℃ 开始，把 $u$ 从 0 改成 0.5 并保持。它使用 0.1 分钟采样，共 2400 个物理更新。默认对象的附带记录恢复出 `gain=8.000000000000007`、`tau=20.000000000000046`、`delay=1.9999999999999403`；显示时可以把它们读作 8℃、20 min、2 min。

![改变增益、时间常数与延迟后的阶跃响应](/results/02-plant/step.svg)

四条曲线中，每次只改变一个量。增大 $K$ 会改变最终温度差；增大 $\tau$ 让相同的变化发生得更慢；增大 $L$ 则把响应整体向右移。图上的扰动曲线用于说明这些参数影响的是模型不同部分，辨识本身用的是无扰动阶跃。

## 模型和单位

对象方程是

$$
\tau\frac{dT}{dt}=T_{\mathrm{ambient}}+d(t)-T(t)-K u(t-L).
$$

| 量 | 默认值 | 单位 | 作用 |
|---|---:|---|---|
| $K$ | 8 | ℃ | 指令从 0 增加 1 时，稳态温度降低的幅度 |
| $\tau$ | 20 | min | 一阶对象的时间常数 |
| $L$ | 2 | min | 指令改变到对象开始响应的延迟 |
| $u$ | 0.5 | 无量纲 | 阶跃期间的制冷指令 |
| $d$ | 0 或 1 | ℃ | 等效热负荷造成的平衡温度偏移 |

没有扰动、$u=0.5$ 时，新的平衡温度是

$$
T_\infty=30-8\times0.5=26\,^{\circ}\mathrm C.
$$

延迟期间队列仍然给对象 0，所以 `step.csv` 在 0 到 2.0 分钟都保持 30℃。第一条受新输入影响的样本是 `minute=2.1`，温度为 `29.9800499168℃`。离散模拟把区间起点记在 CSV 中，因此 `minute=2.0` 这一行仍显示 30℃，而区间更新后的值出现在下一行。

延迟结束后，使用一阶响应的精确离散式：

$$
T_{k+1}=T_\infty+(T_k-T_\infty)\exp(-\Delta t/\tau).
$$

在一个时间常数之后，理论上完成总温差的 $1-e^{-1}\approx63.21\%$。从响应真正开始计时，约 20 分钟时刻是 22.0 分钟，附带记录为 `27.4715177647℃`；它接近

$$
30-4(1-e^{-1})=27.4715\,^{\circ}\mathrm C.
$$

240 分钟末的记录是 `26.000027℃`，所以这是一个接近 26℃ 的稳态阶跃，而不是一条人为画出来的理想曲线。

## 延迟队列怎样工作

`Plant` 为延迟创建 `round(delay/dt)` 个零指令的队列。每次 `step` 先弹出最旧指令，再把当前指令放回队尾。默认长度是 `2/0.1=20`，因此控制器在第 0 分钟发出的输出会在大约第 2 分钟成为对象输入。

这也解释了闭环实验中的一个细节：控制器在 $t=0$ 已经输出了非零制冷，但温度先上升一点。那不是符号错了，而是对象在延迟窗口里仍看到 0。阶跃实验把这个现象从闭环中单独拿出来，便于核对。

当前实现要求 `duration/dt` 和 `delay/dt` 是整数。比如默认的 `delay=2.0` 和 `dt=0.1` 合法；把延迟改成 2.05 而不同时改采样时间会直接报错，不会偷偷把它四舍五入。真实采集系统也必须明确延迟是按样本数处理，还是需要插值。

## 从阶跃数据拟合三个参数

辨识先计算初始温度与当前温度的下降量

$$
\Delta T(t)=T(0)-T(t),
$$

再用带延迟的一阶模型拟合：

$$
\widehat{\Delta T}(t;K,\tau,L)=0.5K\left[1-\exp\left(-\frac{\max(t-L,0)}{\tau}\right)\right].
$$

拟合使用 SciPy 的 `least_squares`，初始点是 `[8,20,2]`，边界是 `gain∈[0.1,100]`、`tau∈[0.1,200]`、`delay∈[0,30]`。代码不会调用 PI，也没有把控制响应曲线混进拟合数据。

因为默认阶跃没有噪声，而且生成数据和拟合公式相同，恢复到 8、20、2 是实现自洽的检查，不是对真实楼宇辨识精度的证明。真实传感器噪声、非线性负荷和非整数延迟都需要另做验证。后面把 $\tau$、$L$ 或扰动换掉，是为了测试整定是否仍然适用，而不是宣称这个三参数模型已经涵盖真实空调。

## 动手：把延迟加长

先只改变对象并重新测阶跃：

```bash
python -m hvac_pid plant --delay 5 --output outputs/tutorial-plant-delay5
```

从 CSV 找出温度第一次不再保持 30℃ 的时间，并读 `identification.json`。然后把同一个延迟带回闭环：

```bash
python -m hvac_pid temperature --delay 5 --output outputs/tutorial-temperature-delay5
```

验证两个事实：阶跃响应的起点延后，PI 输出却仍然每 0.1 分钟更新。比较新旧 IAE 和过冷，解释为什么同一组 Kp、Ki 在更长延迟下可能更容易先把积分推满，再在温度已经越过目标后才收回输出。

不要把这次结果和“重新辨识后再整定”的结果混在一起。这里是固定手工参数改变对象，用来隔离延迟的影响；下一章才会把辨识结果代入 Z-N 和 SIMC。

## 在线位置和计算量

阶跃辨识通常发生在上线前或受控的调试窗口，需要 2400 个物理步（240 min / 0.1 min），并且会主动施加 0.5 指令。它不是每个控制周期都要重复运行的推理器。参考机上这段 NumPy + SciPy 拟合很快，但实际系统的试验时长由温度安全边界决定；本教程没有把它当成可直接部署的自动调试策略。

辨识输出是长度为 3 的向量 $(K,\tau,L)$，单位分别为 ℃、min、min。后面的经典规则、BO 和 FNN 接收这三个标量；在线 RL 接收的是观测向量，不直接读取真实 $K,\tau,L$。下一章先用这三个数算出一组可手算的基线增益。
