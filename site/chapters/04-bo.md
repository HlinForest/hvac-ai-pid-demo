# 04 BO：让每次仿真决定下一次怎么试

经典规则把辨识结果直接变成 Kp、Ki。贝叶斯优化（BO）换一个问题：如果一次完整闭环仿真很便宜，但试验预算有限，能否根据已经测过的 IAE 选择下一组参数？本章的 BO 不参与 0.1 分钟的温度控制；它在闭环开始前反复仿真，每次仿真使用一组固定 PI 增益。

## 最小运行和产物

```bash
python -m hvac_pid bo
```

默认运行 5 个初始样本，再做 15 次 BO 提案，总共 20 次 120 分钟闭环仿真：

```bash
python -m hvac_pid explain --method bo --output outputs/tutorial
```

第二条命令只写解释记录 `outputs/tutorial/explain/bo.json`，用一个实际候选展示编码、GP 预测、EI 和解码结果；第一条命令的完整试验保存在 `outputs/tutorial/04-bo/`：

| 文件 | 内容 |
|---|---|
| `trials.csv` | 每次参数、来源、IAE、过冷、movement 和预测值 |
| `result.json` | 最佳已测参数、预算和运行成本 |
| `search.svg` | 参数平面上的试验顺序与历史最佳 |
| `surrogate.svg` | GP 均值、标准差和 EI 的网格图 |
| `response.svg` | 最佳 BO 参数的温度与输出 |

当前附带参考运行的最佳记录是 `Kp=1.0341153754`、`Ki=0.2378239027`，IAE 为 `48.7412801 ℃·min`。这组结果来自第 5 个初始样本，后面的 15 个 BO 提案没有超过它。教程保留这个事实：BO 有正确的循环，但在这次种子和预算下，额外模型建议没有带来更低的已测 IAE。

## 先定义输入、输出和搜索边界

BO 的一个候选输入是两个增益的向量

$$
x=(K_p,K_i),\qquad x\in[0.01,3]\times[0.0001,0.5].
$$

它把候选放进一个二维的 log 坐标，输入形状是 `(2,)`；每次完整仿真返回一个标量目标 `IAE`，单位是 ℃·min。收集 $N$ 次试验后，GP 输入矩阵形状为 `(N, 2)`，目标向量形状为 `(N,)`。GP 给候选批量 `(1024, 2)` 预测两个形状为 `(1024,)` 的数组：均值 `mean` 和标准差 `std`。EI 也是 `(1024,)`，`argmax` 选其中一个索引。

Ki 的范围跨越三个数量级。若在普通 Kp、Ki 平面均匀采样，小 Ki 区域会被很少访问。因此代码先算

$$
z_i=\frac{\log g_i-\log g_{i,\min}}{\log g_{i,\max}-\log g_{i,\min}},
$$

在 `[0,1]^2` 中拟合和采样，再用指数变换还原增益。图上的轴显示还原后的 Kp、Ki，便于把结果直接放回 PI；GP 实际看到的是无量纲的二维向量。

经典样本有一个边界细节：Z-N 和 SIMC 的精确结果先进入观测集，即使某次公式结果落在 AI 提案范围外；只有随机初始点和后续 BO 候选受 `[0.01,3]`、`[0.0001,0.5]` 约束。这样 BO 不会因为“为了画图”丢掉经典基线。

## 五个初始样本不是五个随机点

`initial_samples` 先做阶跃辨识，然后依次加入：

1. Z-N 参数；
2. SIMC 参数；
3. 用种子 0 在 log 空间采样的三个随机点。

参考 `trials.csv` 的前五个 IAE 是：

| 试验 | 来源 | Kp | Ki | IAE / ℃·min |
|---:|---|---:|---:|---:|
| 0 | ZN | 1.125000 | 0.168919 | 49.3479 |
| 1 | SIMC | 0.288462 | 0.014423 | 77.9950 |
| 2 | random | 0.378296 | 0.000995 | 195.8128 |
| 3 | random | 0.012633 | 0.000115 | 645.4688 |
| 4 | random | 1.034115 | 0.237824 | 48.7413 |

这五次仿真已经说明目标面很不平：Kp、Ki 都很小的第 3 个点让温度误差长期存在；第 4 个点虽然是随机样本，却比 Z-N 略低。BO 后续的 GP 只看这些实际 IAE，不看方法名字，也不会从失败点旁边手写回退到 SIMC。

## GP 到底学了什么

每一轮先用所有已评估点拟合一个固定结构的高斯过程：Matérn 核的长度尺度是 `[0.3,0.3]`，$\nu=2.5$，观测噪声参数 `alpha=1e-6`，目标标准化，且不再优化核超参数。固定它们是为了让这一章的选择过程足够小、可重复；它不是声称这些超参数对所有设备都合适。

GP 在每个候选点给出“当前数据下的预测均值”和“数据覆盖不足带来的不确定性”。均值低通常表示预测 IAE 低，标准差高表示这里还没有充分观测。二者不能直接当成真实温度曲线，候选仍必须运行完整仿真才能得到 IAE。

## 用 EI 选下一个点

目标是最小化 IAE。设已测的最佳值为 $J_{\min}$，预测均值和标准差为 $\mu,\sigma$，则

$$
z=\frac{J_{\min}-\mu}{\sigma},
$$

$$
\operatorname{EI}(x)=(J_{\min}-\mu)\Phi(z)+\sigma\phi(z).
$$

当预测均值已经很好时，第一项鼓励利用；当标准差很大时，第二项给不确定区域机会。

参考运行的第 6 个记录（第一个 BO 提案）来自 `trials.csv`：历史最佳是 `48.7412801021`，候选的 GP 均值是 `87.5345682092`，标准差是 `166.6299701223`。于是

$$
z=\frac{48.7412801021-87.5345682092}{166.6299701223}=-0.23281099,
$$

$$
\operatorname{EI}=48.8725274259.
$$

代码记录的 `ei` 正是 `48.87252742590586`。候选实际参数为 `Kp=0.2101270736`、`Ki=0.2080382822`，运行后真实 IAE 是 `68.8405348558`，高于历史最佳。这个例子把“预测值得试”与“实际一定更好”分开了。

每轮只从 1024 个随机候选中选一个，不在连续平面上求 EI 的解析最优点。候选形状是 `(1024,2)`，所以每轮有一次小型矩阵预测和一次完整温控仿真。

## 读曲线时怎样找失败

![BO 参数选点与最佳得分变化](/results/04-bo/search.svg)

左图的颜色是已测 IAE，编号是试验顺序。右图的折线只画历史最佳，所以它不会向上；后续试验变差并不代表记录被删除。应同时查看 `trials.csv` 的真实 IAE、预测均值和预测标准差：

<!--@include: ../generated/bo-trials.md-->

参考运行中第 5 个初始点已为最佳，15 次提案只是探索了更多区域。这个失败方式很具体：有限预算和固定候选批次没有超过已有样本，并不等于 GP 或 EI 实现错误。改变随机种子、提案预算或边界后，结论可能变化。

另一个常见失败是把 surrogate 图当成温度预测。GP 只拟合参数到 IAE 的关系，图中低均值区域不是“温度会低到哪里”；真正的响应仍在 `response.svg` 和对应 CSV 中。再一个失败是只看 IAE：高 Kp、Ki 组合可能让 movement 和过冷明显增加，BO 当前目标没有自动惩罚它们。

## 练习：多给五次试验机会

```bash
python -m hvac_pid bo --rounds 20 --seed 0 --output outputs/bo-25-trials
python -m hvac_pid explain --method bo --output outputs/bo-25-trials
```

默认总数从 20 次变为 25 次。检查：

1. `result.json` 的 `cost.simulations` 是否从 20 变成 25；
2. `trials.csv` 的第 20 到第 24 行是否都有 `source=BO`；
3. 从 `trials.csv` 的 `iae` 列取最小已测值（或对照 `metrics.json`），检查它是否低于原来的 `48.7412801021`；`result.json` 的 `best` 只保存增益，不要从中读取不存在的 `best.iae`；
4. `explain/bo.json` 里的单轮候选形状和边界是否仍为二维、1024 点、同一 log 范围。

即使最佳值不变，预算字段和新增试验也应正确。不要只挑一条下降曲线来证明多五次“有效”。

## 与完整训练/部署流程的关系

BO 没有 `train` 过程，也没有可保存的网络。它的状态是 `trials` 列表：每次试验包含两个增益和一次完整仿真结果。每一轮读取列表、拟合 GP、选点、追加一行。整个流程结束后只把 IAE 最低的已评估增益交给在线 PI。

因此它适合上线前调试或拿到新对象时的 commissioning：一次默认运行有 20 次 × 1200 个物理步，共 24,000 个模拟步，另有一次 2400 步阶跃辨识。实际耗时和仿真步数一起记录在 `result.json` 及生成的成本表中；秒数会随 CPU、Python 和库版本变化。真实设备上对应的是 20 次试验时长，不能把模拟 CPU 秒数直接当作现场时间。

在线运行时，固定增益只让 PI 每 0.1 分钟算一个标量输出，BO 不在每个采样周期调用。BO 的输入张量只有 `(N,2)`，输出是标量目标和候选向量；没有 GPU 或模型服务依赖。下一章把很多对象上的 BO 结果存成教师标签，再问一个小网络能否在新对象上一次性给出增益。
