# 06 Q-Learning：每两分钟选择一次增益

前五章的方法在闭环开始前给出固定 Kp、Ki。Q-Learning 把“下一组增益怎么选”变成一个离散动作：PI 仍然每 0.1 分钟产生制冷指令，但学习策略每 2 分钟观察一次状态，从 9 组相对 SIMC 锚点的增益中选一组。

## 跑通训练和单步解释

```bash
python -m hvac_pid qlearning
python -m hvac_pid explain --method qlearning --output outputs/tutorial
```

默认训练 500 回合，结果在 `outputs/tutorial/06-qlearning/`；单步计算写入 `outputs/tutorial/explain/qlearning.json`。训练产物包括：

| 文件 | 内容 |
|---|---|
| `model.npz` | Q 表，形状为 `(5,5,3,9,9)` |
| `history.csv` | 每回合 return 和 epsilon |
| `training.json` | 示例 TD 更新、访问状态数和成本 |
| `learning.svg` | 训练回报与探索率 |
| `qtable.svg` | 第 1、250、500 回合的策略切片 |
| `response.svg` | 冻结策略在默认对象上的温度、输出、在线增益 |

Q-Learning 不需要 PyTorch，NumPy 即可运行。

## 状态不是完整的对象模型

每个决策点的原始观测是长度为 5 的浮点向量：

$$
o_t=(e_t,\dot e_t,u_{t-1},s_{p,t},s_{i,t}).
$$

| 分量 | 单位/范围 | 含义 |
|---|---|---|
| $e_t$ | ℃ | 当前温度减设定值 |
| $\dot e_t$ | ℃/min | 上一个 2 分钟区间的误差变化率 |
| $u_{t-1}$ | 无量纲 `[0,1]` | 上一物理步的制冷输出 |
| $s_{p,t}$ | 无量纲 | 当前 Kp / 初始 SIMC Kp |
| $s_{i,t}$ | 无量纲 | 当前 Ki / 初始 SIMC Ki |

它没有读取真实 $K,\tau,L$、延迟队列、未来扰动或完整温度历史。因而这是一个部分可观测表示；不能把这个实现描述成已经满足所有表格 Q-Learning 收敛条件的完整状态。

离散化使用四个分割点把误差和斜率各分成 5 档，输出用两个分割点分成 3 档，当前增益倍数直接映射到 9 个组合之一：

$$
5\times5\times3\times9=675
$$

个离散状态。Q 表再为每个状态保存 9 个动作价值，整体形状是 `(5,5,3,9,9)`，共有 `6075` 个浮点值。状态索引形状为 `(4,)`，动作是一个整数 `0..8`。

## 动作是绝对倍数

每个对象在回合开始前做一次 240 分钟阶跃辨识，用 SIMC 得到锚点 `anchor=(Kp0,Ki0)`。动作将两项增益替换为锚点的绝对倍数：

| 动作 | Kp 倍数 | Ki 倍数 |
|---:|---:|---:|
| 0 | 0.5 | 0.5 |
| 1 | 0.5 | 1 |
| 2 | 0.5 | 2 |
| 3 | 1 | 0.5 |
| 4 | 1 | 1 |
| 5 | 1 | 2 |
| 6 | 2 | 0.5 |
| 7 | 2 | 1 |
| 8 | 2 | 2 |

例如动作 8 是 `(2*Kp0,2*Ki0)`；连续两次选动作 8 仍然是两倍，不会把上一次结果再乘 2。动作 4 是锚点本身，不是失败后的隐式回退。选定动作后，环境把对应 Gains 交给同一个 PI，运行 20 个 0.1 分钟物理步。

## 奖励来自两分钟区间

每个动作的奖励是这段区间 IAE 的负值：

$$
r_t=-\sum_{k\in\text{interval}}|e_k|\Delta t.
$$

如果 20 个物理步的平均绝对误差是 0.3℃，奖励就是 `-20×0.3×0.1=-0.6`。默认 120 分钟有 60 个决策转移；一回合 reward 的不折扣总和等于整段仿真 IAE 的负数。末尾如果不足一个完整区间，环境只运行剩余步数，不会把实验延长到凑满两分钟。

这里要区分训练目标和评估指标。Q 更新使用 `gamma=0.99` 的折扣回报，让较早区间的价值稍微更重要；统一报告的 `IAE` 是完整回合的不折扣绝对误差积分。不能把训练中的折扣 return 直接当成最终 IAE，也不能声称两者在数学上逐项相同。

## 实际发生的一次 TD 更新

更新公式为

$$
y_t=\begin{cases}
r_t,&\text{done},\
r_t+\gamma\max_{a'}Q(s_{t+1},a'),&\text{otherwise},
\end{cases}
$$

$$
\delta_t=y_t-Q(s_t,a_t),
\qquad
Q(s_t,a_t)\leftarrow Q(s_t,a_t)+\alpha\delta_t,
$$

其中默认 $\alpha=0.15,\gamma=0.99$。

参考运行的第一条更新记录（来自 `training.json`）是：

| 量 | 实际值 |
|---|---:|
| `state` | `[4, 2, 0, 4]` |
| `action` | `5` |
| `reward` | `-8.1255066466` |
| `next_state` | `[4, 3, 2, 5]` |
| `done` | `false` |
| `old_q` | `0` |
| `td_error` | `-8.1255066466` |
| `new_q` | `-1.2188259970` |

Q 表从零初始化，第一次访问的下一状态也还没有非零价值，所以 $
\max_{a'}Q(s',a')=0$，目标就是 `-8.1255066466`。因此

$$
Q_{new}=0+0.15\times(-8.1255066466)=-1.2188259970,
$$

与记录的 `new_q` 一致。解释命令读取同一 `training.json` 中保存的 `example_update` 并写入 `explain/qlearning.json`；读者可以按上式手算核对，但这条命令本身不会重新训练或独立重算 Q 更新。

## 训练过程和曲线该怎样读

训练每回合从训练分区随机抽一个对象，每次都用该对象自己的 SIMC 锚点。epsilon 从 1 开始，按回合逐步降到 0.05；探索动作仍然消耗真实环境步数。参考记录的第 1、250、500 回合 return 分别为 `-80.0258`、`-74.0704`、`-55.7562`，但 return 混合了随机动作和不同对象，不能当作默认对象的最终曲线。

![Q-Learning 的训练回报与探索概率](/results/06-qlearning/learning.svg)

附带训练访问到 288 个离散状态，675 个可能状态中仍有许多未访问。评估时策略关闭探索，`argmax` 遇到并列值取第一个动作；完全未访问的状态会选择动作 0。这是代码的确定性 tie rule，不是一个隐藏的安全回退策略。

![训练三个阶段的一张 Q 表策略切片](/results/06-qlearning/qtable.svg)

图中的策略切片固定输出档位和当前增益，只改变误差、斜率档位。数字变化表示 Q 表在不同训练阶段的贪心动作变化；它不是温度预测。

## 冻结后再看闭环

训练完成后保存 `model.npz`，评估阶段不再更新 Q 表和 epsilon。默认对象以自己的阶跃辨识结果计算 SIMC 锚点，再让策略每 2 分钟选择动作：

![冻结 Q 表后的温度、输出和在线增益](/results/06-qlearning/response.svg)

参考运行中，SIMC 基线 IAE 为 `77.9950`，Q-Learning 为 `72.0293`；Q-Learning 最大过冷为 `0.0297℃`，movement 从 `1.3750` 增至 `5.1668`。所以它在这个标称对象和评分下减少了一部分温度误差，却让输出改变得更频繁。两者都来自同一条记录，不能只保留其中一个。

验证分区的平均 IAE 是 `81.4143 ℃·min`，高于默认对象结果；训练对象、验证对象和默认对象不同，且策略仍是离散动作。只看默认曲线会忽略这个差异。

## 一个可复现的失败方式

由于延迟队列没有放进观测，两个具有不同隐含延迟状态的时刻可能被映射到同一离散状态；状态更新会把来自不同阶段的 reward 混到同一个 Q 值里。状态分箱也会丢掉临界点附近的小变化。训练回合增加不一定解决表示缺失。

另一个失败来源是锚点：动作是相对每个对象自己的 SIMC 参数，策略本身不输出绝对 Kp、Ki。若把模型文件配到错误的 commissioning 锚点上，动作倍数仍然合法，但物理增益会整体偏移。比较章节会在新对象上重新辨识 SIMC 锚点，同时保持 Q 表冻结。

## 练习：只改训练回合数

```bash
python -m hvac_pid qlearning --episodes 100 --output outputs/q-100
python -m hvac_pid qlearning --episodes 1000 --output outputs/q-1000
```

用 `training.json` 和 `response.svg` 验证：

1. `cost.episodes`、`transitions` 是否分别变成 100/6000 和 1000/60000；
2. `model.npz` 的形状是否一直是 `(5,5,3,9,9)`；
3. epsilon 末值是否仍由同一公式决定（接近 0.05）；
4. 验证集 IAE、默认 IAE、movement 是否一起变化。

不要从三次运行中只挑 return 最大的一次。一个有意义的验证是看回合预算、表形状和冻结后的闭环是否都符合预期。

## 在线位置和 CPU 成本

Q 表训练是离线过程。参考 500 回合共有 30,000 个两分钟转移和 600,000 个物理步，另有 115,200 个训练对象的 commissioning 步；`training.json` 记录训练耗时约 `5.8869 s`。在线冻结策略每 2 分钟做一次长度 5 的离散化、一个 `(4,)` 状态索引和长度 9 的 `argmax`，默认一回合 60 次调用，这 60 次决策的计算成本应与 PI 的 1200 次标量更新分别计量，不能仅凭调用次数判断谁更快。

Q-Learning 的优势是在线动作选择很小、解释路径清楚；代价是 675 个格子仍然不多，却已经有状态未访问，并且离散动作限制了参数分辨率。下一章用同样的观测、动作、奖励和锚点，把 Q 表换成 `5→32→32→9` 的 CPU 神经网络。
