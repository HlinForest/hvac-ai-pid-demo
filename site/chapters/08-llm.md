# 08 LLM：读完反馈，再试一组参数

这一章让大模型扮演整定实验的操作者：阅读已完成的试验，给出下一组 Kp、Ki，调用仿真工具，再根据反馈继续调整。它每次提出固定参数，不参与两分钟一次的在线控制。

## 配置与运行

使用支持兼容工具调用的模型。PowerShell 示例：

```powershell
$env:LLM_BASE_URL = "https://api.deepseek.com"
$env:LLM_MODEL = "deepseek-flash"
$env:DEEPSEEK_API_KEY = "你的密钥"
python -m hvac_pid llm --live --key-env DEEPSEEK_API_KEY --reasoning-effort none
```

本次采用 DeepSeek Flash。当前接口在关闭思考模式后支持指定工具调用，所以显式设置 `--reasoning-effort none`，详见 [DeepSeek 接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。项目也支持 `--base-url`、`--model`、`--key-env` 参数；其他兼容服务可以省略推理设置。没有失败后切换供应商的分支。

`--live` 显式启用模型调用，默认最多十五轮。不加这个参数只写入“未运行”的记录。缺少配置时保存原因并返回非零退出状态。

## 模型拿到哪些信息

模型获得单位、目标、参数搜索范围、阶跃辨识结果和五个初始试验。初始试验与相同种子的 BO 完全相同：Z-N、SIMC 和三个随机参数。模型不读取配置中真实的 K、τ、L，只读取辨识估计。

每一轮都要调用 `evaluate_gains`，参数是 `kp`、`ki` 和一段简短的调整理由。工具运行完整 120 分钟的仿真，返回 IAE、过冷和输出变化量。

本次第一轮建议来自两个较好的初始样本之间：模型选了 Kp=1.08、Ki=0.20，实际 IAE 为 48.6172。第二轮把两项增益增大到 1.15 和 0.22，IAE 反而上升到 48.7495。第三轮读到这个反馈后，转向较小参数 1.05 和 0.19，IAE 回落到 48.5851。这三轮展示了“提出猜测—试验—根据结果调整”的实际过程。

## 三个角色各负责什么

| 角色 | 负责的事情 |
|---|---|
| LLM | 提议下一组参数，简述调整理由 |
| 仿真工具 | 真正执行参数，计算统一指标 |
| 实验循环 | 保存历史、计数预算、选出已测得分最好的参数 |

模型不能只写一句“效果很好”就获得成绩。评分必须来自仿真。反过来，程序也不会因为参数比 SIMC 差就改用 SIMC 执行；它会把较差结果照实返回，让模型看到这次尝试的后果。

## 错误也是试验过程的一部分

如果模型提供非法格式或越界参数，本轮记录为 `invalid`，反馈具体原因，消耗一轮提案机会，但不增加仿真次数。参数不会被暗中裁剪。若服务超时或断开，保留已经完成的试验，整轮实验标为 `incomplete`。

正常完成后，从所有已评估样本中选 IAE 最低的一组。它可能仍然是初始 Z-N 或 SIMC，这时记录写明“没有超过初始样本”。这是搜索结果，不是运行失败后换算法。

## 动手：沿着一次建议读完整个循环

打开 `08-llm/result.json`，找到一轮记录，依次核对：

1. 请求中的前次试验结果是否完整。
2. 响应是否真的调用 `evaluate_gains`，参数与理由是什么。
3. 仿真返回的 IAE 是否改善，过冷和输出变化是否增加。
4. 下一轮是否根据这个反馈改变建议。

请求与响应会原样保存，但 Authorization 请求头不会写入结果。用量采用接口实际返回的字段；缺失时保留缺失，不推算费用。

要降低单次尝试成本，可用 `--rounds 3` 跑五个初始仿真加三次模型提案。正式与默认 BO 比较时，两者需恢复相同的十五轮提案预算。
