# 05 FNN：把许多次整定压缩成一次推荐

BO 面对新对象时要继续试验。若已经有许多对象的辨识结果和 BO 标签，可以训练一个小型模糊神经网络（FNN），上线前先给出一组 Kp、Ki，再交给普通 PI 闭环。本章的 FNN 是固定高斯前件、可学习后件的零阶 TSK 网络：它模仿有限预算的 BO 标签，不在控制过程中在线更新，也不是一个深层网络。

## 运行、解释和文件

```bash
python -m hvac_pid fnn
python -m hvac_pid explain --method fnn --output outputs/tutorial
```

第一条命令生成 `outputs/tutorial/05-fnn/`，第二条写入 `outputs/tutorial/explain/fnn.json`，里面有一组实际输入的隶属度、27 规则权重、log 增益预测和还原后的 Gains。主要文件：

| 文件 | 内容 |
|---|---|
| `labels.json` | 48 个训练对象和 12 个验证对象的辨识值、BO 标签和试验记录 |
| `splits.json` | 固定的 train/validation/test 对象分区 |
| `model.npz` | 27×2 的规则后件矩阵 |
| `training.json` | ridge 选择、训练成本和默认对象预测 |
| `learning.svg` | BO 标签、网络预测和规则后件 |
| `response.svg`, `metrics.json` | 默认对象的闭环结果 |

测试分区有 12 个对象，只有最后的比较实验使用它们。训练命令不会把测试 IAE 反馈给 ridge 选择。

## 网络真正接收什么

每个对象先经过阶跃辨识，得到三个标量：

$$
x=(K,\tau,L).
$$

输入形状是单对象 `(3,)`，批量形状是 `(N,3)`；单位分别是 ℃、min、min，范围来自 `hvac_pid/fnn.py`：

$$
K\in[8,12],\qquad \tau\in[12,32]\ \mathrm{min},\qquad L\in[1,5]\ \mathrm{min}.
$$

网络输出是两个标量 `(Kp,Ki)`，单位分别为 ℃^-1 和 (℃·min)^-1。实现实际在 log 空间输出 `(log Kp, log Ki)`，最后取指数，因而正增益不会因为线性回归而变成负数。它不读取温度序列、扰动时间、真实对象状态或未来负荷。

## 27 条规则怎样组成

每个归一化输入都有三个中心为 0、0.5、1 的高斯隶属函数。归一化使用

$$
\tilde x_i=\frac{x_i-x_{i,\min}}{x_{i,\max}-x_{i,\min}},
$$

隶属度为

$$
\mu_c(\tilde x_i)=\exp\left[-\frac12\left(\frac{\tilde x_i-c}{0.35}\right)^2\right].
$$

三个输入各取低、中、高之一，组合成 $3^3=27$ 条规则。某条规则的未归一化强度是三个隶属度的乘积，最后除以 27 条规则强度之和。批量前件张量形状为 `(N,3,3)`，规则乘积先得到 `(N,3,3,3)`，reshape 后为 `(N,27)`。

可以用 explain 记录验证一个具体输入。对 $(K,\tau,L)=(10,22,3)$，归一化输入正好是 `(0.5,0.5,0.5)`。中间隶属度是 1，两侧隶属度由代码算为 `0.3604477886`。`features([[10,22,3]])` 的输出形状是 `(1,27)`，中、中、中规则（展开索引 13）的权重是 `0.19621692`；与它相邻、只有一个输入落在侧边的规则权重是 `0.07072595`，三个输入都在侧边的规则权重是 `0.00918890`。这些权重加总为 1，说明预测是平滑加权，不是把对象硬切进一个格子。

这里的批量维度只属于内部矩阵运算：公开的 `explain/fnn.json` 保存单个 `input`，形状为 `(3,)`，以及单个规则 `weights`，形状为 `(27,)`；读取 JSON 时不要把它们误写成 `(1,3)`、`(1,27)`。需要和后件相乘时，代码才临时增加 batch 维度。

## 只学习后件

设 $\bar w_j$ 是第 $j$ 条规则的归一化强度，$c_{j,p},c_{j,i}$ 是该规则的两个可学习后件。预测为

$$
\widehat{y}=\bar W C,
\qquad
\widehat y=(\widehat{\log K_p},\widehat{\log K_i}),
$$

其中 $\bar W$ 形状是 `(N,27)`，$C$ 形状是 `(27,2)`，输出形状是 `(N,2)`。固定前件后，训练就是带 ridge 的线性最小二乘：

$$
C=(W^TW+\lambda I)^{-1}W^TY.
$$

代码用 `np.linalg.solve` 而不是显式求逆，目标 `Y` 是 BO 标签的 log 增益，形状为 `(N,2)`。`ridge` 只约束后件系数，前件中心和宽度不训练。

参考运行的三个候选 ridge 在 12 个验证对象上的平均 IAE 是：

| ridge | 验证平均 IAE / ℃·min |
|---:|---:|
| 0.0001 | 47.3449 |
| 0.001 | 45.9596 |
| 0.01 | 45.6304 |

所以保存的模型使用 `ridge=0.01`。这个选择只看验证对象，之后才用固定模型在测试对象和默认对象上评估。默认对象的预测为 `Kp=0.7855128312`、`Ki=0.1504231524`。

## 教师标签和网络输出要分开看

每个训练或验证对象的标签来自 5 个初始样本 + 15 次 BO 提案，即每个对象 20 次闭环仿真。48 个对象用于拟合后件，12 个验证对象只用于挑选 ridge；验证标签不会再并入拟合矩阵。第一个训练对象的辨识值约为 `(8.715739,24.798263,2.9)`，BO 标签是 `(Kp=0.8830017346, Ki=0.0914364435)`。标签本身是有限预算的已测最佳值，不是理论最优值。

## 训练失败和边界

FNN 的输入范围是训练数据范围。若把 $K=20$ 或 $L=8$ 的对象直接送入 `features`，代码不会抛出“超出训练集”的异常，而会做外推式的高斯加权；这不应被当作已经验证过的泛化。真正的测试范围在 `splits.json`，且所有对象都落在设定区间内。

教师预算不足时，网络可能学到随机样本的偶然性；ridge 过小时，27 条规则后件可能对 48 个训练标签过拟合；ridge 过大时，所有规则输出被过度收缩。当前网络只有 54 个后件参数（`27×2`），不是一个能从原始温度序列自动发现对象动力学的模型。

## 练习：减少教师 BO 预算

```bash
python -m hvac_pid fnn --rounds 5 --output outputs/fnn-rounds5
python -m hvac_pid explain --method fnn --output outputs/fnn-rounds5
```

比较两个运行的 `training.json`：

1. 每个对象的 `cost.simulations` 是否从 20 变为 10（5 个初始 + 5 个提案）；
2. `label_simulations` 是否从 `1200` 变为 `600`；
3. 3 个 ridge 的验证平均 IAE 和最终默认对象 IAE 如何变化；
4. `explain/fnn.json` 的单对象 `input` 形状 `(3,)`、`weights` 形状 `(27,)`、后件 `(27,2)` 是否保持不变；代码内部为了批量矩阵乘法才会把它们暂时写成 `(1,3)` 和 `(1,27)`。

不要用测试对象结果反过来挑 rounds。练习要验证的是教师成本和标签噪声如何影响验证选择，测试集留给比较章节。

## 在线位置和 CPU 成本

FNN 推荐发生在闭环开始前：一次阶跃辨识给出 3 个标量，网络做一次 `(1,27) @ (27,2)` 的小矩阵乘法，再把两项增益交给 PI。推理不需要 PyTorch，参考模型文件只有 27×2 个浮点后件，CPU 成本远小于一次物理采样周期。

训练成本集中在离线标签：参考运行对 60 个 train/validation 对象做了 1200 次仿真、1,440,000 个闭环物理步和 288,000 个辨识步，另有 36 次 ridge 验证仿真。`training.json` 记录的总耗时约 `11.8524 s`，但实际设备上的标签试验时间仍是 1200 次模拟场景的总长度。测试对象不需要重新训练；下一章转为在运行过程中每两分钟选择一次增益。
