# 09 TD3：连续增益、双 critic 和延迟 actor

TD3 把观测直接映射到两个连续增益倍数。它用两个 critic 同时估计动作价值，取较小者构造 target，给 target actor 的动作加平滑噪声，并把 actor 更新频率降到 critic 的一半。这些细节都在一个很小的 CPU 实现里保留，方便把一次 target 计算拆开。

## 运行和文件

```bash
python -m hvac_pid td3 --episodes 500 --seed 0 --output outputs/tutorial
python -m hvac_pid explain --method td3 --output outputs/tutorial
```

结果在 `outputs/tutorial/11-td3/`，包括 `model.pt`、`training.json`、`history.csv`、`learning.svg`、`response.svg`、`TD3.csv` 和 `metrics.json`。`explain/td3.json` 只读取训练记录中的实际首个 replay update。模型文件保存的是冻结 actor 及动作约定元数据；target actor 和 critics 是训练状态，不作为在线策略加载。

## 连续动作和网络大小

TD3 的输入是与 PPO 相同的归一化 `(5,)` 观测，动作是 `(2,)` 的 `float32`：

$$
a=(a_p,a_i)\in[-1,1]^2,
\qquad
K_p=K_{p,0}2^{a_p},\quad K_i=K_{i,0}2^{a_i}.
$$

原始观测单位是 `[℃, ℃/min, 1, 1, 1]`；Kp 的实际单位是 ℃^-1，Ki 是 (℃·min)^-1。actor 结构为 `5→64→64→2`，最后用 tanh 保证动作边界。单条 actor 输出 `(2,)`，批量输出 `(B,2)`。

每个 critic 接收拼接后的 `(state,action)`，输入形状为 `(B,7)`，网络是 `7→64→64→1`，输出 `(B,)` 的标量 Q。actor 参数数为 `4674`，单个 critic 是 `4737`，两个 critic 合计 `9474`；训练同时有 actor、两个 critic 和对应 target 副本。在线只运行 actor，benchmark 中的参数量和 checkpoint 大小要按这个边界读取。

## 收集 replay 和探索

每个回合仍有 60 个两分钟转移。前 256 条经验从 `[-1,1]^2` 均匀随机采样；replay 足够长后使用当前 actor 输出，再加标准差 `0.1` 的探索高斯噪声并裁剪到边界。回放池容量是 10,000，训练 batch 是 64。

一条 transition 保存 `(state, action, reward, next_state, terminated, truncated)`。state/next_state 形状为 `(5,)`，action 为 `(2,)`，reward 为标量负区间 IAE。批量送入 torch 后形状是 `states/actions/next_states=(64,5)/(64,2)/(64,5)`，reward 和 terminated 是 `(64,)`。

## TD3 target 的一次实际计算

对下一状态，target actor 先给动作，再加入标准差 `0.2`、裁剪到 `[-0.5,0.5]` 的 target policy smoothing 噪声，并把结果再裁剪到 `[-1,1]`。两个 target critic 得到 $Q_1^-,Q_2^-$，只取较小者：

$$
y=r+\gamma(1-terminated)\min(Q_1^-(s',a'),Q_2^-(s',a')),
\qquad\gamma=0.99.
$$

两个当前 critic 都用均方误差拟合这个 target：

$$
L_Q=\mathrm{MSE}(Q_1(s,a),y)+\mathrm{MSE}(Q_2(s,a),y).
$$

## 延迟 actor 和软更新

当 update index 是 2 的倍数，先冻结 critic 参数但保留 Q 对 actor action 的导数，使用

$$
L_\pi=-\mathrm{mean}\,Q_1(s,\pi(s)).
$$

随后用 $\tau_{target}=0.005$ 做 Polyak 更新：

$$
\theta^-\leftarrow(1-0.005)\theta^-+0.005\theta.
$$

actor 和两个 critic 的 target 都按同一个软更新节奏变化。策略延迟把 actor 对尚未稳定的 critic 的追逐放慢，但它不替代正确的 replay、done mask 和动作裁剪。

## 训练曲线和失败方式

![TD3 训练回报与损失](/results/11-td3/learning.svg)

500 回合时，训练有 30,000 个转移、600,000 个物理步；warmup 结束后约 29,745 次 critic update，actor 每两次更新一次。`history.return` 是探索动作下每回合 reward 的直接累加，即不折扣的负 IAE；gamma 只用于 critic target。冻结响应才是统一 IAE 的依据。

TD3 的一个失败方式是两个 critic 同时学到相似偏差：取 min 能抑制过估计，却无法修复状态观测缺少延迟队列的问题。target smoothing 如果不裁剪，会把动作带到环境边界外；如果把执行端的饱和值当成 target actor 的原始动作，Q target 也会变。另一个容易错的点是 `terminated` 与 `truncated`：实现只在真正终止时禁止 bootstrap，时间限制边界仍保留 next value。

## 练习：延长训练但固定种子

```bash
python -m hvac_pid td3 --episodes 1000 --seed 0 --output outputs/td3-1000
python -m hvac_pid explain --method td3 --output outputs/td3-1000
```

检查 `training.json` 的 transitions 是否为 60,000、updates 是否按 warmup 后的步数增加；`first_update` 应保持相同的首个 batch 数字，后续 IAE、movement 和 actor 最终参数才可能变化。若 actor 更新次数没有约为 critic 更新的一半，先检查 `policy_delay` 和 update index。

## 在线位置和 CPU 成本

实现依据是 [TD3 原论文](https://arxiv.org/abs/1802.09477) 的双 Critic、目标动作平滑和延迟策略更新。本文保留这些更新结构，改用两层各 64 单元和二维 PI 增益动作。论文的连续控制基准与本项目的温度对象、奖励和训练预算不同，因此只把 TD3 当作成熟基线。

TD3 的 replay、target critics、actor optimizer 都只在离线训练。上线后每 2 分钟只运行一个 `5→64→64→2` actor，动作映射交给核心环境，PI 仍以 0.1 分钟采样；critic 和 target 网络不在线执行。`benchmark` 会用实际 checkpoint 测量 batch=1 的中位数/P95和文件大小；文件大小不等于含 torch 运行时的内存。没有设备服务调用，也没有把训练秒数当成真实空调试验时间。
