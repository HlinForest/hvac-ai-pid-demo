# 09 TD3：连续增益、双 critic 和延迟 actor

TD3 在这个仓库里负责回答一个很具体的工程问题：已经有一组 SIMC 锚点以后，能否用一个确定性策略在二维连续空间里选择 Kp、Ki 的相对尺度。它不是把控制器换成神经网络。策略每两分钟选择一次增益，核心环境再用这组增益运行普通条件积分 PI 的二十个 0.1 分钟步。

实现保留 TD3 的三个稳定化部件：两个独立的 critic、对 target actor 动作的平滑噪声，以及延迟的 actor 更新。训练时这些部件都存在；保存到 checkpoint 后，在线只剩 actor 和动作元数据。下面按一次真实 replay update 的调用顺序说明张量、梯度和持久状态。

这里的 Actor 是从观测产生动作的策略网络；Critic 是给定观测和动作后估计未来折扣回报的网络。回报是负 IAE，Q 越大表示预期累计误差越小。actor 决定“选哪组增益”，critic 只在离线训练中评价这个选择。

## 方法边界和运行对象

连续策略收到的原始观测是

$$
o=(e,\dot e,u,s_p,s_i),
$$

其中 $e$ 是当前温度减去设定点，$\dot e$ 是最近一次两分钟区间的误差斜率，$u$ 是上一个 PI 输出，$s_p,s_i$ 是当前增益相对于该对象 SIMC 锚点的比例。延迟队列不在观测中，因而这是一个部分可观测的输入。

normalized_observation 在送入 actor 前除以 [4, 0.2, 1, 2, 2]，得到长度为 5 的 float32 张量。这个顺序和尺度会写入 checkpoint；加载时 read_checkpoint 会逐项验证，避免控制端拿错观测约定。

actor 输出 a=(a_p,a_i)∈[-1,1]^2。TuningEnv.step_continuous 使用绝对的二进制对数尺度：

$$
K_p=K_{p,0}2^{a_p},\qquad K_i=K_{i,0}2^{a_i}.
$$

因此动作的两个分量是无量纲的，Kp 的单位仍为 ℃$^{-1}$，Ki 的单位仍为 (℃·min)$^{-1}$。动作边界由 actor 的 tanh 和环境的输入检查共同保证。

## 网络、回放和一次环境调用

共享的 make_mlp 生成两层 64 单元、ReLU 激活的 MLP。TD3 actor 是 5→64→64→2，最后一层经过 tanh；参数量为 4674。每个 critic 把 (state, action) 拼成 (B,7)，使用 7→64→64→1，输出 (B,) 的标量 Q，单个参数量为 4737。

训练同时创建 actor、critics、target_actor 和 target_critics。target 副本从当前网络的初始 state dict 拷贝，并设置为不接收梯度。两个 critic 的参数是独立的，即使网络形状完全相同，也不会共享权重。

每个 episode 先从 commissioning 得到的 SIMC 锚点构造 TuningEnv。环境 reset 时建立对象温度、输入延迟队列、PI 的积分输出贡献和五维观测。回合中的一次 environment_step 做四件事：校验二维动作；把动作转成相对锚点的 Kp、Ki；让 PI 连续运行 20 个 0.1 分钟物理步；返回下一观测、这段区间的负 IAE 和结束标志。

ReplayBuffer.push 保存 (state, action, reward, next_state, terminated, truncated)。采样时从最多 10,000 条记录中无放回抽取 64 条，转换后形状为：

| 张量 | 形状 | 含义 |
|---|---:|---|
| states, next_states | (64,5) | 已归一化观测 |
| actions | (64,2) | 原始连续动作 |
| rewards | (64,) | 两分钟区间的负 IAE |
| terminated, truncated | (64,) | 分开的结束原因 |

前 256 条 replay 记录由 [-1,1]^2 均匀采样。之后 actor 的动作再加标准差 0.1 的高斯探索噪声并裁剪到边界。探索噪声只用于收集数据，不进入 target actor 的平滑公式。

环境包装器当前把 step_continuous 的 done 放进 terminated，并返回 truncated=False。更新器仍然只用 terminated 构造 bootstrap mask；这让真实终止和未来可能接入的时间截断保持可区分。

## target：先平滑动作，再取 clipped double Q

td3_target_q 整段位于 torch.no_grad() 中。对 batch 中每个 next_state，target actor 先产生确定性动作，然后添加标准差 0.2 的噪声：

$$
\epsilon\sim\mathcal N(0,0.2^2),\qquad
\epsilon\leftarrow\operatorname{clip}(\epsilon,-0.5,0.5),
$$

$$
a'=\operatorname{clip}(\pi^-(s')+\epsilon,-1,1).
$$

先裁剪噪声、再裁剪最终动作的顺序属于实现契约。这样 target critic 看到的是动作邻域的 Q 估计，而不是只在 actor 的一个尖锐动作上拟合；最终裁剪又确保 Q 网络不会收到环境不接受的动作。

两个 target critic 都评估 (next_state, next_action)，再取较小者：

$$
q^-_{\min}=\min\bigl(Q_1^-(s',a'),Q_2^-(s',a')\bigr).
$$

真正送给两个当前 critic 的 target 是

$$
y=r+\gamma(1-\mathit{terminated})q^-_{\min},
\qquad \gamma=0.99.
$$

terminated 是 1 时不 bootstrap；truncated 不参与这个 mask。target actor、target critics、随机平滑噪声和 target 的所有中间量都没有梯度。

当前两个 critic 在同一个 batch 上分别计算

$$
L_{Q_1}=\operatorname{MSE}(Q_1(s,a),y),\qquad
L_{Q_2}=\operatorname{MSE}(Q_2(s,a),y),
$$

并把它们相加为 critic_loss。target 是一个 detached 的数值参照，所以 critic 梯度只从当前 (s,a) 的 Q 输出回到当前 critic 参数。

训练开始时 target_actor.load_state_dict(actor.state_dict()) 和 target_critics.load_state_dict(critics.state_dict())，所以第一条 target 没有额外的初始化偏差。随后 target_actor.requires_grad_(False)、target_critics.requires_grad_(False)，并切到 eval 模式；当前 critics 则保持 train 模式。target policy noise 的张量形状是 (B,2)，与动作维度一致，不会因为 next_state 是 (B,5) 而错误地广播到观测维度。

critic optimizer 和 actor optimizer 都是 Adam，学习率均为 3e-4。update_td3 先清空 critic 梯度再 backward；actor 分支结束后恢复 critic 参数原本的 requires_grad，避免下一次 critic update 意外跳过梯度。这个参数开关是临时的，不能被当成冻结整个 Q 网络的在线部署配置。

## 两种梯度，以及为什么 actor 要延迟

critic 更新先将两项 MSE 相加，调用 critic_optimizer.zero_grad、backward 和 step。这个顺序让两个 critic 对同一个 detached target 拟合，但各自保留独立的误差方向。

当 update_index % policy_delay == 0 时，代码保存两个 critic 参数原来的 requires_grad 状态，然后暂时把它们设为 false。它没有把 critic 的 forward 从计算图中删掉，仍然计算

$$
L_\pi=-\operatorname{mean}_B Q_1(s,\pi_\theta(s)).
$$

因此 actor 梯度可以沿着

$$
\theta\longrightarrow \pi_\theta(s)
\longrightarrow Q_1(s,\pi_\theta(s))
$$

穿过 Q 的输入动作回到 actor；critic 权重本身不累积 actor 梯度。实现只用 q1 计算 actor loss，两个 critic 仍然都用于 target 和 critic loss。

这两个梯度角色不能混写：critic 让 Q 拟合回报 target，actor 在当前 Q 地形上寻找较高的动作。每个 critic update 都更新，actor 每两个 critic update 更新一次。延迟的作用是减少 actor 追逐尚未稳定的 Q，而不是降低环境调用频率；收集数据仍然每个两分钟决策区间发生一次。

actor 更新完成后，才对 actor 和两个当前 critic 做 Polyak 更新：

$$
\theta^- \leftarrow (1-\tau)\theta^-+\tau\theta,
\qquad \tau=0.005.
$$

soft_update 在 no_grad 中逐参数更新。target actor 和 target critics 在首次复制以后只在 actor 更新的时刻变化；critic-only update 不会让 target 网络变动。它们不在线执行，也不写入冻结 actor checkpoint。

## 从训练循环到记录文件

代码中的训练顺序可以按一条 transition 展开。train 先从 scenario 列表抽取一个对象并 reset 环境；策略或 warmup 采样一个动作；environment_step 推进二十个物理 tick；transition 写入 replay。达到 256 条以后，当前这条 transition 会触发一次无放回的 64 行采样和 update_td3。

update_td3 的调用顺序固定为：先从 target actor/critics 计算 detached target；再用当前 critics 计算两项 MSE 并完成 critic optimizer step；若 update index 为 2 的倍数，再完成 actor optimizer step 和两个 Polyak step。训练记录中的 actor_updated、actor_loss 和 target 数值正是这三个阶段的边界。

500 回合、每回合 60 个两分钟转移，产生 30,000 条 replay transition 和 600,000 个物理步。warmup 后每条新 transition 都触发一次 batch update，所以参考运行约有 29,745 次 critic update；actor 更新约为其一半。

history.return 是收集探索动作时该回合 reward 的不折扣累加，也就是分段负 IAE 的累加。gamma 只进入 critic target。最终比较用冻结 actor 重新从环境 reset，关闭探索，再从生成的响应 CSV 计算整条 120 分钟轨迹的 IAE、过冷和 movement；这两个统计口径不能互换。

训练设置由 training.json 同步记录：学习率 3e-4、gamma 0.99、batch 64、warmup 256、capacity 10,000、policy delay 2、target tau 0.005、target noise 0.2、noise clip 0.5、探索噪声 0.1。CPU 种子同时控制 NumPy replay/环境随机数和 PyTorch 初始化、target 噪声。

## 在线边界、持久状态和测量口径

TD3Policy.choose(observation) 每次调用都把一个长度 5 的原始观测转换成 batch size 1，执行 actor.eval() 和 torch.no_grad()，返回两个 float32 动作。policy 对象本身没有 replay、critic、target、optimizer 或随机探索状态。

策略调用的参数只有当前五维传感器观测和已加载的 actor 权重。控制侧跨调用保留 PI 的积分输出贡献、上一条误差/斜率和上一条指令；这些属于控制器历史。仿真 TuningEnv 另外保存 Plant 当前温度、输入延迟队列和物理步索引，这些是仿真器状态，真实控制器不需要保存或复制 Plant 模型。策略调用后，环境用动作换算 Kp、Ki，PI 在 0.1 分钟周期内运行；到下一个两分钟边界才再次调用 actor。策略不读取延迟队列，也不替代 PI 的抗饱和分支。

checkpoint 的 actor_state_dict 只包含 4674 个 actor 参数，另有 observation scale、[-1,1] action bounds、2**action gain transform、决策间隔 2.0 和训练 config。它不包含 target actor、两个 critic 或 replay 内容。在线加载因此是一次模型加载加每两分钟一次 CPU actor forward；没有模型服务调用。

附带 benchmark 的协议是 batch=1、100 次 warm-up、CPU 单线程、无梯度和无探索，并且计时包含观测转换。参考机器上 TD3 actor 的 1000 次样本中位数为 129.7 μs，P95 为 261.92 μs，4674 个参数，checkpoint 文件为 21,885 bytes。文件字节数是磁盘 artifact 大小，不能当作 Python/PyTorch 运行时 RSS，也不包含解释器、线程库、驱动或安全联锁；这组数不构成任何 MCU 或设备部署保证。

## 失败模式和适用边界

两个 critic 若学到相似的系统性偏差，取 min 只能压低一部分过估计，不能修复五维观测遗漏的延迟队列状态。重复使用同一 critic 作为两个分支也会失去 clipped double Q 的独立性。

target smoothing 若在加噪声后不裁剪，动作可能越过环境边界；若把环境执行端裁剪后的动作当成 target actor 的原始动作，target 分布也会被改变。探索噪声和 target policy noise 是两个不同的量，不能用一个配置替代另一个。

另一个边界是结束标志。当前环境包装器把 done 作为 terminated 返回，但更新 API 明确保留 truncated。将来接入时间限制时，必须维持“真正终止才关闭 bootstrap”的语义，否则最后一段经验的 Q target 会系统偏低。

本实现依据 [TD3 原论文](https://arxiv.org/abs/1802.09477) 的双 critic、目标动作平滑和延迟策略更新，但网络宽度、PI 动作、温度对象、IAE 奖励和训练预算都不同。这里的 reference 数字是本仓库一次 seed 0 运行的记录，不能解释为论文 benchmark，也不能据此声称普遍优于其他方法。
