# 11 七种方法放到同一张考卷上

> **本篇目标**：复现统一比较，解释收益、失败、回退和计算成本。
> **你需要**：第 03 篇的规则（口径不一致不排名）、第 04–10 篇的各算法结论。
> **你会得到**：两张分开的结果总表（v3 封存 / v4 密封）、候选与执行的对照、成本与回退清单。
> **运行方式**：完整复现 `python run.py sealed --artifact-dir <策略目录> --output artifacts/runs/sealed-80x7`。
> **版本依据**：`experiments/manifests/v4.yaml` + `artifacts/runs/sealed-80x7-v4/sealed_provenance.json`。

---

## 这次要解决什么问题

前面每篇只讲一种算法各自的表现，现在把七种放到同一张考卷上。但考卷有两张，来自不同年份、不同出题范围——混在一起排名就是作弊。本篇先讲清楚两张卷子各是什么，再分别给出成绩，最后解释"好是因为什么、差是因为什么"。

## 开始前准备什么

- 前置：全部算法篇（知道每种方法的输出是什么）。
- 输入数据：冻结策略目录（`--artifact-dir`，七种策略同目录版本锁定）+ 密封场景（5×16=80，种子 101/211/307/401/503）。
- 预计资源：560 次闭环仿真（80 场景×7 算法），PC 约数分钟；等效对象时间约 80×5 h。

**流程与结果表结构已固定**（`tools/run_sealed_evaluation.py`）：`sealed_80_details.csv`（560 行逐场景记录，含候选与执行目标、回退标记）→ `sealed_80_summary.csv`（7 行汇总：均值、配对 CI、采用/失败/回退率）→ `sealed_ablation.csv`（随机与保守对照）→ `sealed_provenance.json`（代码/配置/策略哈希）。新增算法或新批次时，只换 `--artifact-dir` 与 `--output`，表结构不变。

## 先跑一个最小实验

```bash
python run.py sealed --artifact-dir archive/outputs_review_v3 --output artifacts/runs/sealed-80x7
```

读哪些输入 → 冻结的七种策略 + 80 密封场景（训练/验证从未见过）。生成哪些文件 → 上述 4 个。怎样判断成功 → `details` 恰好 560 行，`summary` 7 行，`provenance.json` 的策略哈希与 `--artifact-dir` 对得上。

## 刚才发生了什么

每个场景、每个算法、同一个噪声种子各跑一次，六子步 v4 积分器固定。FNN/RL 同时记录候选表与部署表的目标（候选 vs 执行对照）；LLM 用 replay 在训练集上冻结一次（`accepted=false` 则等于 IMC）；另跑 4 组随机增益 + 保守 IMC 公式作消融对照。测试后调参必须换新密封集——这张卷子用完即封存。

## 跟着代码走一遍

- 入口：`run.py sealed` → `tools/run_sealed_evaluation.py:main`。
- 策略：`policy_bundle.py:PolicyBundle.load`——七种策略同一目录，缺文件报错（不再允许各入口自行拼装）。
- 指标：`metrics.py`——同一 J、同一回退拆分字段。两个统计量不要混：**均值之比**（平均数相除）与**逐场景配对目标比均值**（先除后平均 + bootstrap 区间）是不同的量，本篇两个都列。

## 结果应该怎么看

**表 11-1 v3 封存 80 场景**（`holdout_summary.csv`，仅五算法可比，SafeBO/LLM 不在此卷）：Z-N 58.19，IMC 39.53，BO 39.72，FNN 39.26（配对比 0.9979，上界 1.0067，非劣通过），RL 37.61（配对比 0.9595，上界 0.9743，协议内改善）。

**表 11-2 v4 首轮 80×7 密封**（`sealed_80_summary.csv`，七算法同卷，冻结策略来自 v3 批次 + legacy，v4 物理）：

| 算法 | 均值 | 配对比均值 [95% CI] | 读法 |
|---|---:|---|---|
| Z-N | 61.72 | 1.4995 [1.4105, 1.5954] | 显著差于 IMC，地板线实锤 |
| IMC | 41.24 | 1.0（基准） | 回退基准本身合格 |
| BO | 41.95 | 1.0168 [0.9975, 1.0375] | 区间含 1，**不能称优于 IMC**（v3 39.72 vs 39.53 同理） |
| Safe BO | 36.72 | 0.8911 [0.8597, 0.9214] | 显著优，但选中为初始种子（0.3838/0.004441）——证明的是**这组保守参数**，不是搜索机制 |
| FNN | 41.44 | 1.0046 [0.9964, 1.0133] | 上界 ≤1.02 非劣通过；**不足以称显著优于 IMC** |
| RL | 39.83 | 0.9664 [0.9434, 0.9917] | 协议内改善；覆盖掩码一致加载，5% 场景回退 |
| LLM（replay） | 41.24 | 与 IMC 持平 | 训练集无接受候选，回退 IMC；非实时调用 |

> **看哪里**：先看 CI 是否包含 1，再看候选 vs 执行是否一致，最后看回退率。
> **发生了什么**：只有 SafeBO 与 RL 的区间整体落在 1 左侧；BO/FNN/LLM 与 IMC 持平；Z-N 显著更差。
> **这说明什么**："平均目标之比"与"配对比均值"是两个量，报告都列出就是为了防止只挑好看的说。消融对照（随机增益 3–8×更差、保守公式 5.9×更差）说明：BO 类方法的价值首先在于"不是随机"，其次才是"比 IMC 好多少"。

成本与失败清单：BO 14 次评估、SafeBO 7 次（含重复仿真）、FNN 约 4181 等效对象小时、RL 约 4018 h、LLM 每次 5–25 s + API 费用；v4 矩阵 18 次中 17 次回退、3 个 hard_r73 基线本身不稳定（已记 `fallback_failed`，不是模型异常）。

## 改一个参数试试看

假设"密封集是有寿命的"：换一组 `--acceptance-seeds`（如 601,611,621,631,641）重跑密封，观察 SafeBO/RL 的优势是否还在。如果排序稳定，结论更可信；如果翻转，说明 80 场景仍不够——这正是"测试后调参必须换新密封集"的原因。

## 如何确认复现成功

文件检查：`details` 560 行、`summary` 7 行、`provenance.json` 哈希可定位。数值容差：均值允许种子浮动，CI 方向（是否含 1）应稳定。行为检查：LLM 行标注 replay，采用率如实记录。常见异常：拿 v3 表与 v4 表直接排名——两张卷子对象版本与场景清单都不同，**禁止**。

## 这次能得出什么结论

- 在各自协议内：RL（v3/v4 一致改善）、SafeBO 保守参数（显著但归属受限）、FNN（非劣）、BO/LLM（持平 IMC）、Z-N（垫底）。
- 代价排序：RL/FNN 训练最重，LLM 单次最贵，BO/IMC 最轻。
- 适用条件见各算法篇小结；跨协议排名一律不做。
- 未证明的部分：完整 v4 48/16/16 重训后的七算法排名——当前表结构已就绪，新批次进来直接填表，结论到时更新。
