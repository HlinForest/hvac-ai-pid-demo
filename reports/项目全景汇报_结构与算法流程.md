## 1. 项目目标

调研用 AI 方法整定 PI 控制器的两个参数 **Kp（比例增益）** 和 **Ki（积分增益）**，并探索"自整定 / 自动整定算法如何真正落地到空调设备"。落地是关键词：不是只比分数，而是要回答"算法给出的参数敢不敢放到真实压缩机上"。

被控对象是一台机柜/精密空调的简化热模型：压缩机按 0~100% 容量制冷，目标是把室内温度从 30°C 降到 24°C 并稳定在 ±0.5°C 舒适带内，期间还要经受一次"开门 15 分钟灌入 3200W 热负荷"的扰动。

## 4. 共同地基：为什么比较是公平的

### 4.1 热对象（3R2C）

`ThermalPlant3R2C`：室内空气（热容 C_zone）与墙体（热容 C_wall）两个状态，室外经两条热阻漏热，设备/人员/开门负荷直接进入热平衡。压缩机指令 u∈[0,1] 先过**纯滞后队列**（4 min）再过**一阶惯性**（3 min）才变成实际制冷量。传感器带 0.04°C 噪声。这使整定问题有真实的"延迟 + 惯性 + 噪声"，不是玩具一阶系统。

### 4.2 安全 PI 内环

所有算法最终都只是"决定 Kp/Ki"，压缩机命令永远由同一个 PI 计算，并叠加统一约束：0~1 限幅、每分钟 5% 斜率限制、1% 台阶量化、25% 最低运行频率、最小启停时间、**条件积分抗饱和**。所以任何算法比较的都是"参数好坏"，而不是"谁的执行器更激进"。

### 4.3 指标与安全约束

综合目标（越小越好）：

```text
J = 2·IAE + 1.5·ITAE + 10·舒适带超限 + 3·最大过冷
  + 0.35·调节时间 + 0.08·控制变化量 + 0.7·容量指令方差 + 0.015·能耗
```

安全约束（任一违反即"不安全"）：温度必须有限且在 5~45°C、最大过冷 ≤ 阈值、零运行斜率违规、零低于最低频率运行；另有"风险预算"：候选风险分不得超过基线的 1.25 倍。同一增益在噪声下重复仿真多次，用 **J_risk = 均值 + 0.75×标准差** 作为风险目标——波动大的参数直接扣分。

## 5. 七种整定方法逐个讲

### 5.1 Ziegler-Nichols（激进经典基线）

先对压缩机做小阶跃试验，拟合 FOPDT 模型（增益 K、延迟 L、时间常数 τ），再代入 Z-N 公式 `Kp=0.9τ/(K·L), Ti=3.33L`。响应快但易过冲，在本项目代表"经典方法的激进一极"。

### 5.2 IMC 内模控制（稳健全场基线）

同样基于 FOPDT，但主动选闭环时间常数 λ：λ 大则稳而慢。用于性能比较的 IMC **只在训练工况搜索 λ、测试集冻结**——这是两轮评审整改的重点之一：旧版 IMC 用了极保守的默认 λ（积分时间约 911 分钟，与 4~6 小时评估窗口不匹配），被系统性低估（旧目标分 255.8 → 调优后 24.68）。**所有 AI 方法都是在和这位"调过参的 IMC 选手"比赛。**

### 5.3 普通贝叶斯优化 BO（离线全局整定）

在 log(Kp), log(Ki) 空间用高斯过程代理"增益→J"的昂贵映射，用 EI（期望改进）选下一个仿真点，多工况平均 J 为目标，产出一套全局固定参数。适合"只允许固定参数"的低成本控制器。

### 5.4 风险感知安全 BO（RaGoOSE 风格）

在普通 BO 上加第二个高斯过程建模**安全裕量**，只选择"μq + 2σq ≤ 0"的保守安全候选，把噪声方差计入风险。思想来自 RaGoOSE（arXiv:2306.13479），是针对本项目的工程改编。

### 5.5 FNN 模糊神经在线自整定

零阶 TSK 模糊规则面：输入误差 e 和误差变化率 ė（各 5 个模糊档位 → 25 条规则），每条规则存一组离线贝叶斯优化学到的 Kp/Ki，运行时取相邻 4 条规则加权。**先有 BO 当老师，FNN 把老师的知识压缩成查表**。未通过部署验收时自动写成 IMC 回退表，候选表另存审计。

### 5.6 Q-learning RL 离线自整定

状态 = e 档位 × ė 档位 × 压缩机容量模式（5×5×3），动作 = 相对 IMC 的 9 种增益比例，750 回合 × 240 分钟在虚拟环境中训练 Q 表，运行时查表选动作。未访问状态默认"不改增益"（修复了 argmax 全零隐蔽偏置）。明确标注：RL 保留为教学/对照方法，不称 SOTA。

### 5.7 LLM Agent 工具调用整定（本项目亮点）

大模型不碰压缩机、不进实时环，只做"读指标 → 选下一项试验 → 决定停不停"的**低频试验编排**。详见第 6 节。

### 5.8 同场景对比（统一 demo：30°C→24°C + 开门扰动）

| 算法 | 综合目标 J ↓ | 最大过冷 °C | 稳定 | 通过部署门 |
|---|---:|---:|:--:|:--:|
| Z-N | 46.07 | 1.00 | ✓ | 否（回退 IMC） |
| IMC（调优基线） | 46.07 | 1.00 | ✓ | 是 |
| 普通 BO | 51.38 | 1.43 | ✓ | 是 |
| RL | 44.41 | 0.96 | ✓ | 是 |
| LLM Agent（replay） | 45.34 | 0.85 | ✓ | 是 |

读法：AI 方法相对调优 IMC 只有个位数百分点的差异——这正是第 2 节"未达成但真实"的那个结论。

## 6. LLM Agent 整定链路详解

### 6.1 设计哲学：LLM 只有试验编排权，没有安全裁决权

```text
宿主组装 state（增益/指标/预算/安全限/近4步历史）
        │  JSON + 3 个工具定义（strict schema）
        ▼
LLM 策略 decide()：三选一
   ├─ inspect_history  只看不动
   ├─ evaluate_candidate(kp, ki, reason)  申请一次实验
   └─ finish(reason)  收工
        ▼ （若申请实验）
宿主安全门：
   ① 截断到硬边界 ∩ 当前值 ±10% 信任域
   ② 6 个训练工况 × 2 次噪声重复 = 12 次独立仿真
   ③ 判定：安全裕量 ≤ 0 且 风险分改进 ≥ 0.5%？
        ├─ 是 → 更新当前增益，写审计 trace
        └─ 否 → 拒绝并保持原值，理由反馈给 LLM
        ▼ （finish 或 6 步/3 次试验预算耗尽）
部署复核：最终风险 ≤ 基线×1.02 且安全 → 部署；否则回退调优 IMC
        ▼
可见试运行门：在 5 小时 demo 场景再仿一次，开门扰动前未稳定仍回退 IMC
```

关键工程决策：LLM 的 response 只是一个 `function_call`（工具名+参数），**宿主程序执行工具并保留最终裁决权**。工具调用预算（6 步/3 次试验）是硬上限，LLM 无法扩权。

### 6.2 四种 provider

| provider | 说明 |
|---|---|
| `replay` | 录制回放，用于无网络演示；输出中明确标注 "not a live model call" |
| `ollama` | 本地 Ollama（如 qwen3），函数调用 |
| `openai` | OpenAI Responses API，`store:false`，严格单工具 |
| `openai-compatible` | 阿里云百炼 DashScope 兼容端点（默认），可覆盖 base_url 接 DeepSeek/Kimi 等 |

密钥只在调用时从环境变量/`.env` 读取，不落任何报告。`.env` 已被 gitignore。

### 6.3 真实模型矩阵实验（outputs_llm_matrix_v3，18 次真实调用）

3 个模型 × 2 种难度 × 3 个随机种子，全部走 openai-compatible 真实 API。**18/18 次仿真稳定**（安全架构的目标），但**只有 5/18 次** LLM 提出的候选通过全部安全门获得部署，其余 13 次回退调优 IMC：

| 模型 | 难度 | 候选接受率 | 部署率 | 平均目标 J |
|---|---|---:|---:|---:|
| qwen-max | hard | 33% | 67% | 68.62 |
| qwen-max | std | 14% | 33% | 45.38 |
| qwen-plus | hard | 0% | 0% | 68.51 |
| qwen-plus | std | 25% | 33% | 45.21 |
| qwen-turbo | hard | 17% | 33% | 68.01 |
| qwen-turbo | std | 0% | 0% | 45.55 |

（不同难度的 J 不可跨行比较；完整逐次明细见 `outputs_llm_matrix_v3/AGGREGATE_REPORT.md`，由本轮新增的 `aggregate_llm_matrix.py` 生成。）

**结论**：在当前架构里，LLM 的价值不是"调出神仙参数"，而是"用自然语言理由编排试验、在安全门内探索"；当调优 IMC 已接近该对象的可达性能时，安全门会诚实地拒绝大多数候选。这本身就是"AI 整定如何落地"的核心答案——**落地的不是 LLM 的参数，是 LLM + 确定性安全门的组合**。

## 7. 正式实验协议（评审整改 v3）

- 48 训练 / 16 验证 / 16 测试工况三向隔离，每个工况有稳定 scenario_id 和 SHA-256；IMC 的 λ 只在训练集搜索后冻结
- 候选发布前过 5 个新测试种子 × 16 工况 = 80 个密封测试场景
- 结果：FNN 平均目标比 0.9979（非劣通过），RL 0.9595（优约 4%，39.88% 时间采用非 IMC 增益），两者稳定率 100%，新增违规均为 0
- 两轮评审缺陷清单见 `REVIEW_DEFECTS.md`（A 协议公平性 / B FNN / C RL / D 指标 / E 工程卫生，含遗留风险如实标注）

## 8. 落地路径：从仿真到设备

| 层级 | 内容 | 状态 |
|---|---|---|
| 上位机 | 离线整定/训练/Agent，只下发**已验收**参数或冻结策略 | 完成 |
| 实时控制 | 安全 PI 100 ms 循环，AI 调度仅限 2 s 低频建议 Kp/Ki | 完成（仿真+SIL） |
| 嵌入式 | ESP32 PlatformIO 双模式固件；C++ 控制器与 Python 对拍 75 组向量，最大误差 2.98e-8 | 编译通过（RAM 6.7%/Flash 22.6%） |
| 真实设备接口 | `modbus_config.hpp` 寄存器配置，默认 `kWritesEnabled=false`（只读） | 待接真实设备 |
| 上设备前的门槛 | 人工批准、厂家边界、急停、看门狗、影子模式、灰度实验 | 文档明确，未执行 |

LLM Agent **不进入** ESP32 的 100 ms 控制环，也没有写压缩机容量的工具——这是刻意的架构边界。

## 9. 目标达成度评估（诚实清单）

**达成**：方法谱系覆盖（经典→优化→学习→LLM）；公平比较框架；安全门 + 回退的统一落地架构；密封测试协议；嵌入式 SIL 证据；真实 LLM API 矩阵实验；评审缺陷闭环整改。

**部分达成（遗留风险，已在 REVIEW_DEFECTS.md 披露）**：FNN 存在状态混叠与标签冲突（训练 log-RMSE 1.059），部署门因此选择保守 IMC 残差曲面而非高冲突拟合表；RL 状态不含执行器/积分状态，严格 Markov 性不满足。

**未达成**：AI 方法显著超越调优 IMC（对象本身天花板低）；真实硬件闭环（无实体板可靠性数据）；LLM 整定的性能优势（安全门下 13/18 回退）。
